# 运行环境与资源选择

工具接受任意项目路径，不依赖作者的电脑、目录或模型文件。

## 必要环境

- Blender：运行`bpy`脚本，使用其内置NumPy和网格接口。
- 普通Python与Pillow：保存项目记录、拼图、渐变核对页与压缩包。
- 支持WebGL的现代浏览器：打开离线交互查看页。

已验证环境为Blender 5.1与Python 3.12/3.13；其它版本先运行公开测试，不能仅凭接口名称相似就宣称兼容。Windows命令行可使用`python -X utf8`避免中文文件的默认编码问题。

查找当前环境里的可执行文件，例如`command -v blender`或PowerShell的`Get-Command blender`，再将实际路径传入命令。不要在脚本中写死安装位置、用户名或盘符。

这些工具不要求先下载大型图生三维权重，也不要求API密钥。建模代理仍可根据任务选择可用的生成模型或服务，但需要遵守该任务的授权与资源预算，并核对是否会额外获取权重。

## 缺少资源时

列出缺少项、预计下载与磁盘量、运行内存/显存和可选方案，按当前用户的网络及安装限制执行。优先复用可用环境；已有磁盘占用不等于本轮网络流量。不要把一个用户曾经选择的下载阈值或操作系统路径当成所有人的默认规则。

## 本地查看器

`assets/model-viewer.min.js`及许可文件随技能附带，生成的HTML不需要CDN。脚本拒绝需要未附解码器或远程资源的GLB；可先用本地工具导出普通内嵌PNG/JPEG贴图的GLB。第三方代码的许可独立于本项目的MIT许可。
